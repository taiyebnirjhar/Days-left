# Days Left (personal Android app)

Owner: Taiyeb Nirjhor, senior frontend engineer. Personal-use app, Samsung SM-M145F (Exynos 1330, 8 cores, 5.5 GB RAM), Android 15, arm64 only.
Plain Java, no androidx, all views built in code. Keep it that way. Package `com.taiyeb.daysleft`.

## Build
- `gradle assembleDebug --no-daemon -q` (AGP 8.10.1, compileSdk 36, minSdk 26, NDK 27.2.12479018, cmake 3.22.1, abi arm64-v8a only)
- Set `ANDROID_HOME` first. APK: `app/build/outputs/apk/debug/app-debug.apk`
- Bump `versionCode`/`versionName` in `app/build.gradle` and the "Days Left X.Y" label in MainActivity.java each delivery. Current: 3.47 (61).
- Dependency: `com.tom-roush:pdfbox-android:2.0.27.0`. whisper.cpp is vendored in `app/src/main/cpp/whisper` (CPU only), wrapped by `cpp/jni.cpp`.

## Features
Countdowns (status bar, notification, overlay) + Library: eye-friendly PDF reader, audiobook (m4a) playback synced to the book.
- Pins: manual page<->audio-time anchors.
- Find my page (audio -> page) and Play this page (page -> audio): instant from sync data, else probe by listening (Whisper) + PageMatcher.
- Full-book sync: `SyncService` (foreground, resumable from the stored anchors) transcribes short samples with whisper.cpp, chosen by `SyncPlanner` (seed at the playhead, adaptive-stride extension both ways, then gap bisection; v3.25 maps a ring of +-150 s first (ready after ~5 calls) then widens to +-10 min in the same service (STAGES in SyncService; model download and book text extraction also run there); v3.20 maps only +-10 min around the playhead (`reach`, ~2 min on the tiny model) and follows the playhead via `recenter`, the service idles while the player plays; whole book = reach infinity, ~13% of the audio; simulate with `tests/host/simrun.sh`), `Aligner` maps words to book positions, `Alignment` stores time<->word. `BookIndex` holds words, per-word boxes, sentence ends. Reader highlights the spoken sentence and follows with page turns.
- Speed model (measured, see tests/host/whisper/README.md): one whisper call costs the same for any clip up to 30 s (~10 s tiny / ~26 s base on the phone), so everything is built to use few calls: `Whisper.transcribeBatch` splices up to 3 clips (9 s) into one call and uses word timestamps (`nRunWords`, auto-disabled via `wordPending`/`noWordMode` if it ever crashes natively); `SyncPlanner.nextBatch` makes independent pieces; thread count is auto-tuned on the first 4 calls (`wThr`). Play page / Find page ask `SyncService` (`goalWordReq`/`goalTimeOut`, `hereWord`), planner goal = interpolation search by book word (~2.3 calls from nothing in sim); `ReaderActivity.prefetch` locates the page you rest on in the background.
- Accuracy model: the sentence highlight needs probes <= 25 s apart (`Reader.HL_GAP`, gated by `Alignment.gapAt`; no highlight beats a wrong one), page turns <= 60 s. `SyncPlanner.dense` (on after the first ring) keeps probes 12 s apart from 40 s behind to 150 s ahead of the playhead, 30 s within 5 min, 90 s beyond; `recenter()` is called every service loop so that zone travels with the playhead (sim: highlight available 100% while listening, median error 0.3 s). Page starts (`GOAL_GAP`) are only answered when bracketed by probes <= 25 s apart.
- Dense-first (v3.31): the very first call after the seed fills the zone around the playhead (3 probes per call, DENSE_NEAR = 20 s apart, 150 s ahead / 40 s behind; first highlight after ~1.2 calls in sim), the coarse ring/widening comes after. Probe search windows are tight (predicted position +- margin) so repeated common phrases cannot win; `Aligner.consistent` drops matched words whose timing is off the straight line (Theil-Sen); `Alignment.pauseBetween`/`gapAt` refuse to highlight inside a gap whose pace is < 55% of the usual (pause/music) and the planner probes such gaps. `tests/host/simrun.sh` reports availability/wrong highlights/error, sweep with `JOPTS="-Ddn=16 -Dna=100"`.
- `SyncService.ready` = the zone around the playhead is >= 90% mapped (turns off below 60%), re-checked every loop by `updateReady`, so it turns off after a jump; `statusText()/statusPct()/etaSeconds()` are the single source for the notification, the pill and the panel (ETA restarts whenever `ready` changes and is never shown above 15 min; v3.32 showed 'Synced' next to a notification saying '15% - about 1 h 41 min left').
- v3.32 fixes from the user's log: (1) `recenter()` re-places the walking cursors when the playhead leaves the stretch they work on (after Play page jumped far, the dense zone kept mapping the old place and the highlight was lost); (2) gaps wider than `GAP_MAX` (300 s) are islands, never bisected (a far search made it listen to the whole audio); (3) the audio file takes ~10 s to open: `AudioClip.warm` does it while the model/book text are prepared, three decoders run side by side (`decodeMany`) and stay open between service runs; (4) thread tuning compares ms per second of audio (calls differ in length); (5) progress = readiness of the zone around the playhead (`zoneProgress`), one wording for pill and panel (`syncStatus`); (6) every wait dialog has Hide (keeps working, the answer arrives as a tappable pill via `postResult`) and Cancel (stops it); (7) the hint row has a fixed height so the controls do not jump. Measured on the phone: speech ~2.0 s + 0.17 s per second of audio, decode ~0.9 s per piece.
- UX (v3.31): status pill above the player (`updateBanner`: model download, reading the book, 'Syncing around you… N% · about S s', battery-saver hint, 'Ready ✓' flash with a haptic tap, 'Sync paused… tap to try again'); the sync thread runs at THREAD_PRIORITY_DISPLAY; settings row 'Offer to sync when I press Play'.
- UX: first Play on an unsynced book asks (`askSync`: benefits, be patient, keep listening/reading; 'Sync and play' / 'Just play' / 'Don't ask'), the panel hides itself after 9 s and a toast says when it is ready. Unset model = tiny.
- Audio decode (`AudioClip`) keeps the opened file and the codec between clips (flush) and drains without 10 ms waits; it retries once fresh on any failure.
- Settings -> Debug log (`Dbg.java`): file log, copies for sharing. Records Java crashes and, on API 30+, why previous runs ended (native crashes show as CRASH_NATIVE). Use it, do not guess.

- v3.36 end-to-end test (`tests/e2e/run.sh [scale] [scenarios]`, details in the file header): builds three synthetic audiobooks with a KNOWN timeline from public-domain text (neural voices, robotic voice + 12 dB noise + numbers, skipped sentences, spoken intro, page numbers/footnotes glued in, AAC), runs the app's real pure-Java `SyncCore` (the sync loop, shared with `SyncService`), `SyncPlanner`, `Aligner`, `Alignment`, `Highlight` with real whisper tiny.en (`tests/host/whisper/drv.cpp` in serve mode) and modelled phone latency, then scores the highlight the reader would show (`switchError`). Checks: first highlight median <= 45 s, zone ready p90 <= 90 s, >= 98.5% of shown highlights correct, shown >= 85% (80% on corpus C). Results v3.36 (scale 1, play): A 99.8%, B 99.6%, C 99.6% correct. Needs `truth_tsv.py` for each corpus (run.sh does it). Cannot cover: MediaCodec decode, UI, Android services.
- v3.36 rules found by the test: `Alignment.withBook` credits SENTENCE_PAUSE_S of silence per sentence end when interpolating (boundaries land where the audio has them); `highlightWordAt` hides the highlight inside gaps where unread text is likely (words/s > FAST_GAP x usual) unless the gap is <= 3 s, and the planner probes such gaps; `Aligner.paceHint` rejects clusters whose pace is implausible (absolute band 1.2-6 words/s); `Highlight.sentenceFor` shows nothing on page numbers/lone figures; `SyncPlanner.voids` marks stretches that were listened to but have no speech (intro, music) so 'ready' does not wait for them; DENSE_NEAR 14 (was 20: +10 s to the first highlight, wrong highlights 11 -> 2 on A).

- v3.37 touch lock (like VLC): padlock in the reader's top bar hides the controls and `ReaderActivity.dispatchTouchEvent` swallows every touch and Back while `locked`; any touch shows an unlock padlock (bottom middle) for 3 s, tapping it unlocks. Audio, highlight and page-follow keep running. Not verified on device.

- v3.38 fixes from the user's log (audio = a 'Must Listen' MP3 of Psycho-Cybernetics, a DIFFERENT version of the text than the PDF: it skips ~5,600 words at the start and only partly matches; Deep Work, a true reading, synced perfectly): (1) `SyncPlanner.recenter` restarted the seed search on EVERY call while the playhead was not near anything mapped (paused at 21 s: the same 3 probes 10+ times, then 'Lost the place'); now a playhead that has not moved (< 5 s from `startSec`) never restarts it. Restarting while the playhead MOVES is kept (the e2e corpus C drops from 84% to 79% shown without it); (2) re-placing the cursors needs the playhead to have moved > 2 s (`placedAt`), else the backward search never advanced; (3) failed probes only count as 'settled voids' if < 6 words were heard (`Req.heard`), otherwise a failed seed showed 47% progress with nothing mapped; the pill says 'Finding your place in the audio…' below 3%; (4) a backward search that gives up is 'lost' only if < 3 anchors exist (an intro that is not in the book is not lost); (5) model download resumes (Range) and retries 6x; (6) every 'no match' line in the Debug log now says why (`Aligner.lastWhy`). Sim check 1e (`tests/host/simrun.sh`): audio opens with 7 min not in the book, playing and paused. Lock icon: same size as 'Aa', unlock padlock at bottom middle.

- v3.41 marker latency: the reader used to learn about new sync matches by re-reading the alignment file at most every 10 s, so the marker lagged by that much. Now `SyncService.live` (a fresh `Alignment` per batch, `liveItem`/`liveVer`) is handed over in memory and `ReaderActivity.onTick` (every 100 ms, was 250) swaps it in at once; the file reload is only the fallback when no sync has run. `BookText.clearAudioData` clears `live`. What stays slow by design: a place nothing was mapped for needs ~1-3 speech calls (~20-30 s on the phone) before a marker can be shown without risking a wrong one; opening the book wakes the service for the resting position so it is usually mapped before Play.

- v3.46 marker never lost + zoom ready early (user: 'marker should be almost real time, never ever lose it; the zoom should only make me wait if needed'): `MarkerTrack` (pure Java, tests/host/MarkerCheck.java, run by run.sh) decides the shown sentence every 100 ms: while PLAYING it never loses the marker (where the sync timing is too sparse for `Alignment.highlightWordAt` the marker advances by dead reckoning at the narrator's pace, `typicalWps()`, else `averageWps()`, else 2.5 words/s, up to 150 s, and the page follows it) and is corrected as soon as real timing returns (forward at once; a step BACK must last 1.5 s and is ignored while estimating); a seek into audio nothing is known about shows no marker (a wrong one is worse); a pause keeps it. Found by the test: `typicalRate` only measures pairs of anchors 0.5-4 s apart, so an alignment with one anchor per probe has no pace (0) - hence the fallbacks. The zoom is prepared before it is needed: opening the Aa panel (`warmZoom`) reads the book's word positions if missing and renders the sharp page pictures around the reader, scrolling warms the next page (`rfPicture`, cache of 4). NOT verified on device.

- v3.47 ZOOM REMOVED, margins polished (user: 'fuck it, remove our zooming mechanism; polish trim margins; I read in portrait and rotated'): the re-wrapped zoom (`ReflowView`/`WordFlow`, Text size slider, v3.39-v3.45) is deleted; the page has its ORIGINAL pinch zoom (1-5x, pan) and double-tap zoom again, nothing is enforced; the word cursor is gone too. Lessons kept: (1) PDFBox calls `writeString` once per printed LINE; `BookText.BoxStripper` now gives every word its OWN box (index `MAGIC` 0xB00C0003; an older index is discarded by `BookText.ready()` and re-read quietly by `readBookQuietly`, word numbers unchanged so alignments stay valid; the per-word boxes also make the sentence marker tighter); (2) test layouts with the app's REAL extraction on a real PDF (desktop PDFBox 2.0.27 from Maven Central works), a test with made-up boxes passed while the app broke; (3) `BookText.Disp` / tx_<id>.txt (printed words, font size, bold/italic) is still written but nothing reads it. Trim empty margins: `computePageBounds` (printed text area per page from the index) -> `computeCrop` takes the margin that 90% of pages respect (10th percentile per side), saved per book (`trim_<id>`) so it is there at once on the next opening, falls back to the old pixel scan only when the book is not read and nothing is saved; `cropOf(bitmap, page)` ALWAYS adds a page's own text area back, so text is never clipped and all pages share one size. Rotation: `PageView.onSizeChanged` resets zoom/pan (a zoom from the other shape left the page off screen); the activity handles rotation itself (`configChanges`), the page is fitted into whatever shape it gets (portrait or landscape) with the same crop. ## Gotchas
- Nothing may depend on the reader screen: model download, book text reading, sync, Find/Play page searches and prefetch all run in `SyncService` (foreground, survives leaving the app). The reader only polls statics (`dlPct`, `textPct`, `goalTimeOut`, `hereWord`) and wakes the service in `resumeSync()` / `Player.play()` / `onTick` when the playhead is outside the mapped area.
- `SyncPlanner.widen()` must reset `fwdDone/bwdDone`, otherwise a wider window is never filled (v3.28 only ever mapped +-150 s; covered by the 'two rings' check in `tests/host/simrun.sh`).
- `getInsetsController` NPE: call immersive() only after the view is built.
- startForegroundService requires startForeground right away in onStartCommand, for EVERY start request including ones that are ignored (stop, already running, nothing active). v3.34 crashed with ForegroundServiceDidNotStartInTimeException because SyncService returned early; `tests/host/check_services.py` (run by run.sh) fails if any service returns before startForeground().
- Whisper has a global abort flag (`Whisper.abort`); SyncService.stop sets it, service start clears it.
- Host tests for PageMatcher/Aligner/BookIndex were plain `javac` programs (not in repo).

## In-app update
`Updater` reads the latest GitHub Release of taiyebnirjhar/Days-left (asset *.apk), downloads it and installs through PackageInstaller. `.github/workflows/release.yml` builds and publishes `v<versionName>` on every push to main that touches `app/**` (skips if that release exists), signed with the key in `signing/dl.keystore.enc` (AES-256 encrypted; the short repo secret `SIGNING_PASSPHRASE` decrypts it in CI; a long base64 secret got corrupted when pasted from a phone). Never change that key: updates would stop installing. `app/build.gradle` signs debug builds with `DAYSLEFT_KEYSTORE` (set by CI) and the workflow fails the release if the APK's certificate differs from the secret's. Releases v3.18-v3.29 were signed with random throw-away keys or not published (the secret was ignored/corrupt): only releases whose workflow run passed the 'Check the APK is signed with the key' step update over each other; anything older must be uninstalled first. Host tests: `tests/host/run.sh`.
